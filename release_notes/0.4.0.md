# Release notes: 0.4.0

This release covers changes since 0.3.22.

## Highlights

- Added `bl edit <repository_name>` to convert a managed repository into an editable/full checkout. It disables sparse checkout, refetches full history and content, removes the BL locking hook, and persists the editable state.
- Added per-project configuration under XDG config home at `$XDG_CONFIG_HOME/bl/<project>/config.ini`.
- Added an automatic CLI version check, with `-N` / `--no-check-version` to opt out.
- Added a commit-locking pre-commit hook for managed repositories, directing users to run `bl edit <repo>` before committing.

## Behavior changes

- Repositories marked editable in config are skipped during build processing.
- The spec parser now uses `ruamel.yaml` instead of PyYAML.
- Repository specs can include a boolean `editable` field, defaulting to `false`.
- Git subprocesses now disable terminal prompts with `GIT_TERMINAL_PROMPT=0`.

## Fixes

- Shallow repository detection now handles trailing newlines from Git output.
- BL-generated pre-commit hooks can now be removed when entering editable mode.

## Dependencies and runtime

- Python requirement is now `>=3.12`.
- Removed `pyyaml` and added `ruamel-yaml`.
- Added `xdg-base-dirs`.
- Packaging version is now dynamic, and the runtime version comes from `bl.__version__`.

## Migration notes

- Environments using Python older than 3.12 need to be upgraded.
- The CLI may contact PyPI for the version check unless disabled with `-N` / `--no-check-version`.
- Managed repositories now get blocking commit hooks; use `bl edit <repo>` before making local commits.
